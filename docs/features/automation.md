# 自动化

源码 owner：`packages/features/automation`。Runtime 与 renderer 是 optional Feature；main/preload 复用已有 typed Feature operation transport，不新增原生桥接。

侧栏自动化入口进入任务列表与对话。设置对话以 Core 的 featureId 归属自动化，不进入普通对话列表；执行对话进入普通对话或所选项目，Core 的 origin 记录自动化来源与任务 ID，侧栏对话尾部显示时钟图标。新建任务复用未填写的草稿，否则创建专属持久对话，并写入仅模型可见的任务创建指令；保存任务后解除草稿引用。旧设置对话按内部种子消息识别并迁移，同时删除相邻的旧欢迎种子消息；执行对话按任务账本解除隐藏、补齐来源与已有项目绑定，保留实际对话记录。首次发送前由 Automation 提供居中的引导内容，复用宿主 ChatStarter 与 Composer；点击发送后立即进入正常对话，不再写入或展示开场欢迎消息。创建对话不展示环境信息面板，侧栏标题右侧的「+ 创建」菜单提供 AI 对话与手动填表两种入口。选择 AI 对话进入设置草稿；从已有任务或运行记录手动新建时使用独立设置草稿，不切换当前对话。Agent 用 `request_user_input` 补齐缺失字段，通过 `manage_automation` 保存任务，结果在对话中显示可打开编辑表单的任务卡片。表单持有任务名称、执行内容、所属项目、重复规则、时间、模型、强度及每次新建聊天选项。所有任务在此电脑运行。

任务表单通过 renderer host 注入模型选择器，与聊天菜单共用品牌图标、供应商分组、名称/代码/供应商搜索和键盘选择。Runtime 列出已启用供应商的全部配置模型；模型的 `enabled` 只标记供应商默认项，不影响单个任务的可选范围。页面和对话结果卡片打开的表单共用该选择器，选择仅修改任务模型，不改变聊天或全局默认模型；切换模型会清空旧思考强度，编辑保存也移除被清空的持久字段。

宿主发送展示 hook 按 Composer 身份保存待发送气泡，使用与 runtime 请求相同的 `clientId` 合并消息/队列回传；不修改持久线程 snapshot 或事件序号。忙碌对话与 Goal 输入仍进入队列，失败移除待发送气泡，由原有发送动作恢复草稿。发送锁由 Workspace 保持，避免引导页切换后 Composer 重挂载丢失正在提交的状态。

运行记录在侧栏常驻，汇总全部任务并按执行时间倒序排列，不随当前任务或新建对话切换。任务列表按内容高度排列，最多占侧栏高度的一半，运行记录紧接任务列表；两者分别滚动，侧栏总高度与顶部操作区保持稳定。两种条目共用 AutomationSidebarRow，统一文字对齐、字号、行高、间距、圆角与选中背景。点击记录按运行 ID 单选，进入对应执行对话并定位到该次运行的起始消息；历史消息尚未加载时自动向前分页，定位后不再跟随会话底部。所属任务仍提供顶部操作，但任务行与运行记录不同时高亮。任务右键菜单复用工具栏的编辑、暂停/恢复、立即运行与删除行为，目标不依赖当前选中的任务。

任务标题与操作通过宿主 AppRouteTopbarPortal 接入公共栏：macOS 放在窗口顶部，Windows 放在内容区 header，按钮和标题沿用聊天页的样式。自动化侧栏使用宿主侧栏轨道与宽度，不受 Windows header 显隐影响；内容区与 header 使用同一主背景，仅由公共底边线分隔。

## 调度与持久化

- 自动化工具的常驻系统提示只包含稳定规则。Agent 在创建或管理任务前通过 `manage_automation(mode="list")` 按需获取当前本机时间、当前对话 ID、模型、项目和任务；动态数据仅进入工具结果，不在每次采样时重写系统提示前缀，以保留对话缓存复用。
- 支持单次、分钟间隔、每天、工作日、每周及自定义星期。表单与对话按本机日期和时间创建任务，日历规则自动补齐本机计算设置，旧记录的日历元数据仍可读取；不存在的夏令时时刻跳过，当地时间重复时只执行一次。
- 数据保存到 runtime dataDir 下的 `features/automation/tasks.json`，带 `schemaVersion: 1`。串行 mutation queue 与临时文件 rename 保证写入完整后才发布内存 snapshot。
- 应用运行期间每 5 秒检查到期任务；关闭应用或电脑睡眠期间不能执行。恢复后对错过的循环执行合并为一次，再计算下一未来时刻，不补跑一串历史轮次。
- 数据迁移与 WebDAV prepare 把调度器中执行和排队的 mutation 计入 readiness；队列排空后同步暂停调度及任务写入，维护期间不预约运行、不推进执行时间、不创建对话。解除维护后检查原先到期的任务，单次任务仍可执行。
- 同一任务不重叠运行。暂停只停止后续调度，正在执行的对话可通过现有停止按钮取消；暂停状态仍支持立即运行。
- 执行前先持久化运行预约与下一次时间，再绑定执行对话并启动 turn。应用重启将未完成运行标记为 interrupted，不重放已经预约的任务。记录最近 50 次执行，实际对话保留在 Core thread store。
- 默认复用独立执行对话；开启每次新聊天时创建新 thread。创建对话与执行对话分离，保存的 prompt 作为真实用户消息进入普通 agent loop。
- 项目字段在创建时省略则继承来源项目，显式 null 表示普通对话；编辑时省略保留原项目。Agent 从项目列表选择真实 ID，不能依靠提示词中的项目名称绑定目录。同一来源项目可继承 worktree，其他项目使用自己的目录。更改任务项目后开启新的执行对话，历史对话保留原归属；运行中禁止更改项目。每次执行前验证项目仍可用，失败写入运行记录，不退回其他工作目录。

## 无人值守边界

`AutomationRuntimeHost` 由 runtime composition adapter 提供 thread 创建、模型查询、启动与运行状态读取。只有这个可信调用路径向 `AgentLoop.startTurn` 的内部 execution 参数设置 `unattended`；REST/app-server 的 `SendTurnInput` 不暴露该参数。

无人值守策略在每个 sampling step 重读设置后重新应用 `full-access`，不写入全局配置。内置用户输入工具不下发，并拒绝迟到的表单调用；插件交互立即失败，MCP 表单/URL 信息征询直接 decline。缺少必要信息或凭据时，agent 应在结果中说明阻塞并结束任务。普通对话继续沿用原有权限与表单设置。

协作子代理的首次启动和邮箱唤醒从调用轮次的可信 execution context 继承 `unattended`；模型参数与 HTTP 输入不能设置该策略。子代理仍使用只读工具与只读权限，只读调用不等待人工批准，写入调用继续被拒绝。

任务定义与调度账本由 Feature 持有；对话、工具执行、取消、消息、usage 与 SSE 仍由 Core 持有。Renderer 只查询 Feature snapshot，复用当前对话的 SSE owner，不建立第二套线程投影。

普通侧栏沿用宿主摘要同步：空闲时每 5 秒发现后台创建的执行对话，运行中每秒更新状态，不必重新启动应用。来源标记同时保存在事件、checkpoint 与 SQLite 摘要中，重命名或删除任务后仍能识别已有执行对话。

## 验证

定向测试覆盖日历边界、时区与夏令时、间隔错过执行时间、并发到期、暂停、独立/复用对话、启动失败、重启恢复，以及真实 agent loop 中每步的完全访问与表单隔离。Runtime REST 集成测试覆盖真实定时触发、持久对话、重启后的结果恢复以及任务编辑/暂停/删除。
