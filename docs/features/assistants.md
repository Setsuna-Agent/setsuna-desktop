# 助理与 QQ 连接器

`packages/features/assistants` 拥有助理身份、助理会话归属、项目任务关联、定时消息和消息回报。Core 仍拥有线程、执行、队列、审批和线程事件；项目表单不保存 Bot 配置。

## 产品入口与对象

- 本版只开放一个助理配置入口，首页“新会话”下面展示其头像与名称；已有历史身份保留在存储中，不自动删除。点击入口直接在首页的 `chat` 路由打开助理对话，项目和会话侧栏保持不变，不再注册独立助理页面。`Cmd/Ctrl+4` 从任意主页面打开同一助理，复用统一快捷键设置和悬停提示；未配置助理时不启用。宿主 `useAssistantConversationEntry` 为点击与快捷键共享打开动作和防重复请求，仍通过原有导航确认与迟到结果守卫；快照在后台读取，不阻塞首屏。右键菜单编辑或删除同一助理；没有配置时显示创建入口，有配置后不提供新增入口。
- 助理头像、名称、QQ 连接状态与最近任务放在聊天里的虚拟环境信息浮动面板中，复用原有环境信息的显示开关和自适应布局，不创建或展开右侧工作区面板。配置表单直接从首页入口打开，不切换当前对话；宽弹窗中左侧为助理信息、模型和项目授权，右侧为 QQ 配置与来源列表，空间不足时自动改为单栏。
- 一个助理始终只有一条活动会话。桌面、所有已授权 QQ 私聊和群聊使用同一 Core 线程，连续上下文与压缩记忆也随该线程持久化；不同助理保持各自的线程。重复打开、跨入口消息及重启不创建另一份聊天。打开会话是幂等操作，仅首次创建或原记录被删除后补建。
- 助理表单配置名称、头像、性格、模型、思考强度、授权项目及 QQ AppID，字段布局复用共享 `sd-form-*` 样式。授权项目使用可搜索多选下拉，收起显示“首项 +N”，保留全选与取消全选；快照从现有项目元数据带入图标和配色，由宿主注入 ProjectIcon，授权仍只保存项目 ID。头像入口与项目图标共用 TextField 的交互前缀，嵌在名称输入框左侧；紧凑弹层顶部为配色与重置，下方为助理专用图标和图片上传。预设包含机器人、人物、客服、智能、专业与陪伴形象，未配置时使用默认文字色的机器人；原有已保存图标、配色与上传图片仍正常显示。AppSecret 通过本机密钥存储保存，不进入 Feature JSON、快照或模型上下文；留空保持原密钥。连接状态仅在已有信息面板显示，编辑表单不再展示连接状态行。
- 助理聊天使用左右气泡和分组时间戳，只展示用户消息与助理回复，隐藏思考过程、工具调用和压缩记录；自动压缩仍在后台执行。底部单行输入框保留发送/停止操作，`+` 和 `/` 共用附件、插件与 Skill 菜单；选中的能力引用随本次消息发送。菜单不提供模型、协作、Goal、Review、手动压缩或清空上下文操作，未匹配可用能力的 `/` 内容仍按普通消息发送。
- 助理会话实际发送的模型与思考强度沿用助理配置，强度优先于同模型的通用输入偏好；修改配置后同步到已有助理输入框。助理新建的项目工作对话也继承当时的模型与强度，执行配置随任务持久保存，排队、恢复或后续助理配置变更不能把已接收任务降回模型默认强度。工作对话的输入框以该任务配置为初始值，不修改通用模型偏好；续接原有工作对话保留其任务配置，普通已有对话和旧任务不补写或虚构历史强度。
- AppSecret 输入框提供显示/隐藏和复制操作，已保存的密钥仅在点击时经专用 typed operation 读取。明文只由当前编辑器临时持有，查看或复制不修改待保存的替换值；关闭编辑器或清除密钥后丢弃临时明文。
- QQ 配置提供“Markdown 回复”开关，默认开启，旧配置缺少该字段时也按开启处理。开启后使用 `msg_type: 2` 和 `markdown.content` 发送 QQ 支持的简单 Markdown；关闭后使用 `msg_type: 0` 和 `content` 发送普通文本，助理指令同步使用纯文本格式。保存后下一条发送立即读取新设置，不重连 WebSocket；被动回复的消息 ID、序号和 outbox 重试机制保持一致。协议依据：[QQ 官方 Markdown 消息说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)。
- QQ 配置标题右侧的“接入说明”在当前编辑弹窗内切换到教程页，不再叠加弹窗。返回、关闭说明或按 Esc 回到原表单，保留未保存字段、滚动位置和入口焦点；教程页不触发保存或关闭编辑器。教程涵盖创建机器人、选择 WebSocket、填写凭据并启用、发送首条消息及允许来源，并提供开放平台与官方指南链接。说明内明确要求同一 AppID 仅在一台设备或一个机器人程序中启用，当前不提供跨设备占用检测或互斥；换机需先停用旧连接，聊天记录和任务不自动迁移。
- 一个 AppID 只能绑定一个助理。私聊和群聊首次出现时进入待授权列表，只有桌面端允许后才能使用助理的项目权限。未授权期间，每条新私聊消息或群 @ 消息都回复授权提示；QQ 重复投递同一条消息时不重复回复，也不启动助理轮次。提示携带与设置列表相同的来源名称：有昵称时使用昵称，否则使用“私聊/群聊 · 编号”，便于找到对应条目。这是本机访问控制，不是 QQ 平台的群数量或主动消息配额。
- QQ 来源只保留允许或移除，不提供会话选择或配对。来源列表单行显示名称与操作，不展示聊天预览。私聊来源优先显示平台消息提供的用户昵称，昵称随新消息更新并持久保存；消息未带昵称时保留已有名称，从未拿到昵称时继续显示来源类型与编号，不提供备注入口。群成员昵称不会误作群聊名称。私聊与群成员信息标在消息来源上，用于区分发言及回复收件方，不再决定助理的记忆归属。
- 任务列表在信息面板中使用单行条目，项目和状态收进悬停提示。右键可重命名、置顶/取消置顶、删除；置顶状态持久保存并优先排列，其余按更新时间倒序排列，任务与定时提醒合计最多显示 5 项，置顶项也计入上限。任务重命名只修改任务账本，不改共享的项目对话标题。
- 已保存的定时消息也在同一列表展示，使用时钟图标；执行状态和下一次时间收进悬停提示。点击已执行提醒定位到同一助理聊天的最近执行轮次，重复点击仍可定位。右键重命名、置顶和删除使用原有菜单；删除会取消提醒及尚未发出的 QQ 消息，保留聊天记录。
- 点击任务直接切换到其原项目对话，执行、文件修改和审批复用该对话能力。导航在创建/打开助理入口前取得请求归属，迟到的打开结果不能覆盖用户后来选择的普通对话。删除已结束任务仅移除对应账本记录，项目对话及其他任务保留；进行中的任务不能删除，任务管理操作不触发额外导航。
- 旧版按来源拆出的记录在后台归并：先固定一个共享入口并更新任务归属，再逐条导入尚未存在的消息及压缩记忆，最后归档原记录并记录 `mergedInto`。原始证据不删除，失败或繁忙保留待导入状态，重试不会重复消息。恢复旧入口会重定向到原助理，不会误选另一位助理。删除助理时同时清理这些历史备份，项目执行对话仍保留。

## 纵向调用链

```text
首页助理入口 / AssistantConversation / 复用 ChatRouteAdapter 和环境信息面板
  -> typed Feature operation / 普通线程 startTurn
  -> AssistantsRuntime + AssistantToolHost
  -> AssistantTools -> AssistantAccess -> AssistantTaskCoordinator
  -> AssistantsRuntimeHost -> Core 项目线程 / AgentLoop / 原有审批
  -> 持久线程事件 -> 任务账本 -> 独立报告轮次
  -> 助理会话 -> QQ delivery outbox -> 官方 QQ OpenAPI
```

- `contracts/`：配置、会话映射、任务、回报、校验器、typed operations 和宿主端口。
- `runtime/directory.ts`：身份、模型绑定、项目授权、共享入口和 QQ 来源允许/移除。
- `runtime/conversations.ts`：唯一会话归属、旧记录归并与任务报告归属迁移。
- `runtime/sidebar-entries.ts`：侧栏条目的归属检查、标题与置顶持久化、删除边界。
- `runtime/access.ts`：授权项目、普通项目对话和历史读取的统一边界。
- `runtime/tasks.ts`：独立任务生命周期、同工作目录排队、事件跟踪、恢复和报告合并。
- `runtime/reminders.ts` / `reminder-tools.ts`：自然语言定时消息的工具、日历预约、来源绑定、恢复去重和暂停取消。
- `runtime/deliveries.ts`：QQ 持久 outbox、轮次归因、逐块发送回执和退避。
- `runtime/qq/`：官方 AppAccessToken、WebSocket Identify/Resume/心跳重连、私聊与群 @ 消息解析；兼容 `GROUP_AT_MESSAGE_CREATE` 与 `GROUP_MESSAGE_CREATE`，后者仅接受 `mentions.is_you` 明确为真的消息，避免回复普通群聊内容。
- `renderer/`：共享快照、助理聊天、信息面板、编辑器、QQ 来源授权和任务列表。
- 宿主 `composition/assistants-runtime-host.ts` 对接 Core、本机密钥和代理网络；renderer `composition/assistants/` 注入头像、模型控件、导航和现有聊天界面。

## 执行与恢复约定

助理只获得明确的编排工具：列授权项目、检索/读取历史、派发/查询/补充/取消任务、回答关联的审批或输入请求。助理会话的独占工具目录同时限制模型下发和真实执行；即使 Feature 未加载或已卸载，持久会话归属也使桌面文件、shell、动态工具、协作和 Goal 入口保持关闭。

新建工作对话采用项目默认 Skill，优先使用助理配置的模型与强度；未配置助理模型时沿用项目默认模型。续接保留原对话配置。同一工作目录的助理任务串行，同一对话使用 Core 原有队列；显式并行创建 Git worktree。任务关系、执行配置、提交 `clientId` 和提交意图先落盘，再调用 `startTurn`。恢复时按 `clientId` 查询 Core 中的输入和轮次；不因丢失响应重新执行。无法证实已提交的意图标为中断，而非冒险重放。

任务属于助理，桌面和已授权 QQ 来源可接续同一项工作；其他助理不能查询或控制它。项目访问、任务控制、历史读取和结果回传重新检查授权。授权撤销不会自动回滚已执行的文件修改；尚未提交的等待任务不能继续启动，未发送的任务结果也不能继续回传。

报告只由排队转运行、新审批/输入及终态等有依据的事件触发，不转发每个工具日志或虚构百分比。短时间事件合并，全部写入助理的共享会话；需要回传 QQ 的报告按发起来源分别发送。助理当前忙时延后，报告使用自己的轮次，避免借用另一条交流的 QQ 接收方。报告 ID 稳定，Core 的持久 mailbox 回执支持重试去重。

Feature 账本位于 `dataDir/features/assistants/state.json`，采用串行事务与临时文件替换；线程正文和工具记录仍只保存在 Core 线程存储。启动只加载账本，旧记录导入、任务对账、补交和 QQ 连接在后台进行；关闭后不允许迟到恢复重新连接。导入仅在相关线程没有运行、取消清理或待提交修改时取得短期独占权；繁忙时退后重试，大历史按批让出事件循环，不等待它才能提供 runtime 核心服务。

QQ 的回复先记录 outbox，再跟踪对应轮次结束。发送失败只重试回报，不重新启动助理或项目任务。长文本逐块发送，已确认块落盘后不再重发；QQ 成功响应与本地写入之间的进程崩溃仍存在分布式发送的重复窗口，不承诺端到端 exactly-once。错误 `40034100` / HTTP 429 至少退避一分钟；没有本机人为设置的群主动消息数量上限，最终可用性仍以平台授权和接口响应为准。

QQ 消息 ID 按平台提供的非空字符串完整保存，不套用本地 ID 的长度上限；群消息 ID 可能超过 128 个字符。收件记录、任务来源和回复关联使用同一校验，重启恢复不得截断或因较长 ID 导致整个助理 Feature 加载失败。

## 定时消息

用户在 QQ 中说“每天早上九点给我发消息”时，助理通过 `assistant_manage_reminder` 保存提醒，成功后才确认下一次执行时间。工具支持查询、创建、修改、暂停、恢复和取消；查询同时返回本机时间、时区及最近 QQ 发送结果，不能在接口失败时宣称已经送达。单次、分钟间隔、每天、工作日、每周和自定义星期使用 Automation contracts 中相同的日历 codec、工具 schema 和计算函数，不创建系统 cron 或后台 sleep。

提醒把 QQ 收件方、群内发起者及 Bot AppID 保存为来源，后续消息自动回到原私聊或群聊，不复用创建请求的过期 `msg_id`。QQ 来源只能查询和管理自己发起的提醒，桌面可管理此助理的全部提醒；来源撤销、QQ 停用或 AppID 更换会阻止执行和补发。桌面创建的提醒只在助理聊天中产生回复。

每五秒在后台检查到期项，助理当前忙时保留预约，空闲后在同一全局聊天启动独立 mailbox 轮次，并沿用助理模型和推理强度。执行前持久化预约 ID 与本次指令，Core 的持久 mailbox 回执可找回已接受的轮次，覆盖 Core 已执行但 Feature 尚未保存回执的崩溃窗口。重复请求相同来源、内容和日历规则时复用现存启用提醒；同一提醒不重叠执行，定时轮次也不能再次创建一份提醒。修改尚未接受的预约会替换旧计划，排队中的到期检查重新核对执行时间。

调度仅在 Setsuna Desktop runtime 运行且电脑未休眠时执行，不提供关机唤醒或云端调度。恢复后，错过多次的重复提醒合并成一次，下一次重新计算到未来；已预约的一次性提醒仍可执行。暂停和取消会撤销尚未发出的 QQ 消息，恢复从未来时间开始。QQ 发送失败沿用 outbox 退避，只重发消息，不再生成同一次内容；平台权限和频控仍以真实接口响应为准。

提醒预约、QQ 连接和恢复均在后台启动，挂起或失败不会挡住 runtime health 和核心会话列表；维护期间不预约，关闭后迟到结果不再登记新回报。执行沿用助理的编排工具边界，涉及项目操作仍通过项目任务和原有审批，不借用 Automation 的完全访问执行权限。

## 验证与接入

```bash
corepack pnpm@7.33.7 run test:unit packages/features/assistants/test
corepack pnpm@7.33.7 run test:integration packages/desktop-runtime/test/integration/agent-loop/assistant-isolation.test.ts
corepack pnpm@7.33.7 run test:integration packages/desktop-runtime/test/integration/runtime-server/assistant-reminders.test.ts packages/desktop-runtime/test/integration/assistants-startup.test.ts
```

这些测试使用真实 Feature 状态存储、Core AgentLoop 与 SQLite，替换远端模型、WebSocket、HTTP 发送及本机密钥边界，覆盖唯一会话、历史归并与失败重试、繁忙及启动边界、持久提交、工作目录串行、重启对账、助理间隔离、QQ 来源归因/去重/分块补交/频控、授权撤销及工具隔离。定时消息还覆盖实际 QQ 输入到模型工具、持久化、重启触发、原聊天生成和原 QQ 回发的完整链路，以及取消、修改时序、来源隔离和发送失败不重复执行。

真实 QQ 联调需要在助理编辑表单输入自己的 AppID/AppSecret、启用连接，并在平台完成相应授权。私聊发消息或群内 @ 后，在同一表单允许对应来源。普通审批可通过原来源答复；复杂权限授权、MCP elicitation 等仍需在 Setsuna Desktop 中处理。没有真实 QQ 凭据和平台会话时，自动化测试不代表账号级连通性或群授权已验证。
