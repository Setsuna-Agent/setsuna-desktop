# Setsuna Desktop UI/UX 设计规范

本规范面向 macOS / Windows 桌面工作台、共享 UI 和第一方 Feature。设计方向是：**让对话、输入和工作成果占据主要空间，以紧凑、稳定的桌面控件组织操作。**

本文统一 App shell、Chat、Workspace、Settings、Capabilities、Automation、Pull Request 及共享控件的视觉基础、交互约定与验收标准，作为新增和修改 UI 的设计依据。

本文负责设计取舍与使用规则；具体组件 API、业务状态机和运行链路仍由对应 owner 文档维护。本文不授权扩大功能、增加界面说明文案或批量重做页面。

## 1. 设计原则

1. **围绕当前任务组织界面。** 阅读回复、继续输入、处理审批、检查文件是主路径；配置、诊断和运行详情按需进入。
2. **用布局建立层级。** 优先使用对齐、间距、字号与中性表面区分区域。强调色留给主要动作、链接和明确选中语义；不要把所有状态做成彩色徽章。
3. **保护连续操作。** 切换页面、刷新数据、展开工具详情不应丢失草稿、选区、滚动位置或用户的展开选择。异步结果必须回到发起操作的会话、项目和目录。
4. **紧凑操作，舒适阅读。** 工具栏、文件树和菜单维持桌面密度；对话和文档保留阅读宽度与行距。不能通过缩小正文解决空间不足。
5. **同一行为保持一致。** 同类控件共享外观、焦点与禁用语义；业务差异留在内容、布局和状态处理层。
6. **文案与动效都要克制。** 图标沿用 tooltip 和可访问名称。不得为“更清楚”追加常驻说明、状态摘要、引导语，也不得把用户要求删除的文字换位置放回。

## 2. 信息架构与页面职责

### 2.1 工作台区域

| 区域 | 承载内容 | 设计规则 |
| --- | --- | --- |
| 全局图标栏 | 对话、PR、自动任务、插件应用与全局设置入口 | 入口位置稳定；切换局部侧栏不改变全局入口；图标使用 tooltip 与 `aria-label` |
| 页面侧栏 | 当前页面的项目、会话、设置分类、能力目录或任务列表 | 只承担当前领域的定位与切换；长列表自身滚动；选中态与 hover 分开 |
| 顶部栏 | 当前对象标题、历史导航、上下文操作与窗口控件 | 标题可截断，操作保持可命中；不承载额外说明、统计汇总或重复的页面导航 |
| 主内容区 | 对话、设置表单、能力详情、PR 内容 | 一个明确的内容主体；正文和长列表按所属区域滚动 |
| 右侧 / 底部工作区 | 文件、审查、浏览器、终端及侧对话 | 标签、大小和会话生命周期由宿主协调；收起与关闭是不同操作 |
| 临时浮层 | 菜单、选择器、短表单、确认与媒体预览 | 浮层类型由任务决定；使用共享定位、关闭与焦点机制 |

实现入口：[AppReadyLayout](../apps/desktop/renderer/src/app/layout/AppReadyLayout.tsx)、[AppNavigationRail](../apps/desktop/renderer/src/app/layout/AppNavigationRail.tsx)、[Workspace 编排](desktop/renderer/workspace-and-debug.md)。

### 2.2 页面模式

| 模式 | 已有场景 | 规范 |
| --- | --- | --- |
| 对话工作台 | 主对话、侧对话、自动任务关联对话 | 输入区与消息阅读区共用宽度基线；工具活动从属于所在轮次；保留检查成果的面板入口 |
| 分类与表单 | Settings | 分类导航 → 分组 → 字段；简单偏好不套多层卡片；相关字段共享保存边界 |
| 目录与详情 | Plugin、Skill、MCP | 列表用于定位，详情用于了解和编辑；不把详情字段堆回列表或操作栏 |
| 列表与工作对象 | PR、文件、Review | 列表定位与详情操作分离；筛选、选中、滚动与编辑状态保持各自身份 |
| 运行管理 | Automation、运行中心 | 配置和运行记录分开；运行结果可回到对应任务；页面切换本身不终止后台工作 |

新增界面优先套用已有模式。只有确实需要新的工作方式时才增加布局类型；不要为了填满空白增加仪表盘、统计卡片或装饰区域。

## 3. 视觉基础

### 3.1 Token 与主题

[tokens.css](../apps/desktop/renderer/src/shared/styles/tokens.css) 是宿主视觉 token 的来源；[外观偏好](../apps/desktop/renderer/src/shared/preferences/useAppearancePreferences.ts) 和主题 hook 负责解析用户选择。数值表用于说明设计基线，实际代码引用 token，不复制表中的字面值。

| 语义 | 使用的 token | 用法 |
| --- | --- | --- |
| 主画布 / 内容表面 | `--app-bg`、`--app-surface` | 承载正文、表单、弹窗；通过布局和必要分隔区分相邻区域 |
| 次级表面 | `--app-surface-subtle`、`--app-surface-muted` | 嵌入内容、字段组、代码等局部区域；避免卡片再套卡片 |
| 窗口与导航 | `--app-shell-bg`、`--app-sidebar-bg`、`--app-sidebar-text*` | 跟随侧栏背景预设，不在各 Feature 自配一套侧栏颜色 |
| 文本 | `--app-text`、`--app-text-secondary`、`--app-text-muted`、`--app-text-subtle` | 按内容重要性分级；弱化文本仍要可读；当前 secondary 与 muted 是同值别名 |
| 分隔 | `--app-border`、`--app-border-strong` | 普通边界与交互边界；不能只靠极浅分隔表达关键状态 |
| 主要操作 | `--app-primary`、`--app-primary-hover`、`--app-primary-text` | 按钮背景与文字成对使用、成对校验 |
| 反馈 | `--app-success*`、`--app-warning*`、`--app-danger*` | 成功、警告、错误与破坏性操作；不跟随用户强调色改变语义 |
| 中性交互 | `--desktop-agent-control-*-bg`、`--desktop-agent-sidebar-*-bg` | 工具栏、列表与侧栏的 hover / active；不把整行染成强调色 |
| 菜单 | `--app-menu-*` | 操作菜单的背景、高亮和几何；保留独立于强调色的蓝色选中语义 |
| 键盘焦点 | `--app-focus-ring`、`--app-primary` | 用于按钮、链接等非文本输入控件的既有反馈；输入框不添加聚焦外框 |

当前浅色主画布为 `#ffffff`、正文为 `#242424`；深色主画布为 `#181818`、内容表面为 `#202020`、正文为 `#e4e4e4`。这是现有中性基底，不另建品牌配色体系。

主题规则：

- 支持浅色、深色、跟随系统；默认强调色为 neutral，已有 blue / purple / green / orange 预设。
- 用户选择的字体、强调色、侧栏背景与密度由宿主统一应用。Feature 不自行持久化第二套宿主主题。
- 普通文字按钮、发送按钮、文字链接分别检查实际前景与背景；选用了 token 不等于已经满足对比度要求。
- 操作菜单沿用独立蓝色高亮；输入框上方的命令、Skill、插件和 `@` 候选沿用不透明表面与中性选中态，防止下方正文透出。
- 品牌图标、文件类型图标、代码高亮、Diff 与 Git 分支颜色有各自语义，不机械改成 primary。菜单中的品牌底板使用既有 `data-menu-color="preserve"` 机制。
- 第一方 scoped Feature 优先消费已有 `--sd-color-*` 映射；共享控件沿用 `--app-*`。Tailwind 由 [beui.css](../apps/desktop/renderer/src/shared/styles/beui.css) 映射，不能成为另一套主题来源。

### 3.2 字体与阅读层级

界面默认使用系统字体栈，代码使用 `--app-code-font-family`。现有 Geist / Inter 等选项继续由用户偏好控制；不要为单个页面增加网络字体。

下表把已有字号归入明确角色，供后续选型；它不是要求一次性替换所有字号。

| 角色 | 基线字号 / 行高 | 字重与场景 |
| --- | --- | --- |
| 对话、文档正文 | 14px / 1.72 | 随 `--app-font-weight`；保持长文阅读节奏 |
| Composer 输入 | 14px / 24px | 随字体偏好；与正文协调，独立于工具栏字号 |
| 常规操作、表单标签、列表标题 | 13px / 18–20px | 正文或 500；不能把主标签弱化到元信息层 |
| 文件树、菜单、辅助字段 | 12px / 18–20px | 紧凑扫描；整行命中区不随字形缩小 |
| 次要元信息 | 11px / 16px | 仅用于时间、路径补充、计数等；不用于关键操作和错误正文 |
| 面板标题 | 13px / 18px，500 | 文件、终端等嵌入工作区 |
| 通用小页标题 / 弹窗标题 | 16px / 24px，600 | 局部编辑与独立小任务 |
| 设置页标题 | 18px / 26px，600 | 配置页面 |
| 对象详情标题 | 22px / 30px，600 | Plugin、Skill 等对象详情 |
| 能力目录标题 | 24px / 32px，400 | 浏览型目录；不扩散为所有工具面板的大标题 |

现状的界面字重偏好默认值为 500；CSS 中的 400 是偏好初始化前的兜底值。不要据此再生成一套“默认字体配置”。

正文、用户输入和错误详情允许自然换行。侧栏标题、标签名和紧凑列表可以省略，但完整内容应通过已有 tooltip、详情或打开对象访问。路径与模型 ID 等机器标识不能改变真实复制值。数字对齐优先使用 `font-variant-numeric: tabular-nums`，不是把整段说明换成等宽字体。

对应实现：[Markdown](../packages/renderer-ui/src/styles/markdown.css)、[共享控件](../packages/renderer-ui/src/styles/controls.css)、[详情](../packages/renderer-ui/src/styles/detail.css)、[Settings](../apps/desktop/renderer/src/features/settings/styles/settings-base.css)。

### 3.3 间距、控件尺寸与表面

**新增布局的间距选择：** 优先用 4 / 8 / 12 / 16 / 24 / 32px；2 / 6px 用于紧凑控件内部。相邻内容越相关，间距越小。已有 10 / 14 / 20 / 28px 等值可能来自控件内部或阅读边距，不为凑刻度机械替换。不预先创建大量间距变量；反复出现且有稳定语义时再由所属层抽取。

| 项目 | 当前基线 | 使用规则 |
| --- | --- | --- |
| 标准按钮 / 字段 | `--app-control-height: 32px` | 表单和普通操作默认尺寸；内容与 padding 可能使实际高度更大 |
| 小按钮 / 大按钮 | 最小高度 28 / 38px | 小按钮用于密集操作；大按钮用于已有宽松表单场景 |
| Shell 图标操作 | 28px 命中区，14px 图标 | 顶栏、右侧与底栏共用；不把图标尺寸当作点击范围 |
| Composer 主按钮 | 30px | 发送 / 停止 / 排队保持同一位置和占位 |
| 菜单 / 文件树行 | 26px 基线 | 文件树层级缩进 16px；行操作保留整行命中 |
| 圆角 xs | 6px | 紧凑 ghost 控件、chip |
| 圆角 sm / md | 均为 8px | 字段、图标按钮与列表操作；保留已有别名 |
| 圆角 lg | 10px | 小浮层等现有表面 |
| 圆角 xl | 18px | Composer、Dialog、设置表单组 |
| 圆角 control / full | 999px | 普通文字操作按钮；不用于把整个工作区卡片化 |

圆角按控件职责选择。菜单外框 10px、菜单项 5px，Workbench 外框与部分详情分组的 12px 是现有局部几何；Windows 窗口外沿 8px 是系统裁切约束。它们不能通过修改一个全局卡片圆角强行统一。

操作图标复用现有 `lucide-react`，按所在控件选择 14 / 16 / 18px；同一工具栏保持尺寸、描边和对齐一致。文件类型复用 `FileIcon`，厂商与模型图标复用已有品牌映射。图标大小与点击范围分开管理，不为追求紧凑把需要明确动作名称的按钮全部改成图标。

表面使用规则：

- 主工作区和并排面板用连续画布与细分隔，不为每个区域添加圆角、边框和阴影。
- 内容分组优先采用空白或一种弱表面；仅在分隔有必要时加边界，避免“底色 + 边框 + 阴影”重复强调。
- 所有文本输入框、搜索框、多行输入和组合控件的内部输入，聚焦时均不添加 outline、额外描边或光晕；外层容器也不通过 `:focus-within` 补加外框。保留控件原有边框和常驻阴影；Composer 使用 `--chat-prompt-shadow` 常驻阴影，聚焦不跳变。
- 浮层使用已有 `--app-shadow-popover`、`--app-shadow-modal` 等语义阴影。普通卡片不借用 modal 阴影。
- 交互状态只改变必要属性；按钮按下不缩放、不位移，避免菜单锚点和命中位置移动。

## 4. 布局、密度与窗口适配

### 4.1 现有尺寸与权属

除原生窗口尺寸外，以下数值按 100% 应用密度下的 CSS 像素理解。

| 区域 | 现状 | 来源 |
| --- | --- | --- |
| 主窗口 | 默认 1320 × 860，最小 880 × 640 | [Electron main](../apps/desktop/main/src/index.ts)；原生逻辑尺寸 |
| 全局图标栏 / 顶栏 | 48px / 42px | [shell.css](../apps/desktop/renderer/src/app/styles/shell.css) 与 tokens |
| 页面侧栏 | 默认 240px，拖动范围 208–360px | tokens 与 [useDesktopPanelResize](../apps/desktop/renderer/src/features/workspace/hooks/useDesktopPanelResize.ts) |
| 主内容保留宽度 | 单区 420px，分屏计算使用 520px | 面板 resize hook |
| 右侧工作区 | 默认按可用空间等分；最小 410px；用户拖动后保留自定义尺寸 | 面板 resize hook；不能把 CSS 的初始 clamp 当作最终宽度算法 |
| 底部工作区 | 默认 228px，范围 180–520px；计算时为主区保留 260px 高度 | tokens 与面板 resize hook |
| 对话阅读区 | 主对话最大 750px、侧对话 680px；左右留白 28 / 20px | Chat 样式 |
| 设置 / 能力内容 | 普通设置最大 720px，能力目录与通用详情 750px | Settings、Capabilities、Detail 样式 |
| 弹窗 | 默认宽 640px，确认框 420px；有视口最大宽高限制 | 共享 Dialog / ConfirmDialog |

这些宽度服务于不同内容，不收敛成一个通用的“页面最大宽度”。PR Diff、编辑器、表格等宽内容在所属容器内延展或横向滚动。

### 4.2 空间不足时的规则

1. 以实际工作台 / 面板可用宽度判断布局，扣除图标栏和相邻区域；不要只看屏幕分辨率。
2. 延续现有侧栏自动折叠与环境信息自动收起机制，尊重用户显式展开、收起和调宽。
3. 主内容与工作区不能同时容纳时，应让当前操作有完整可用区域，并保留切回另一侧的入口。优先复用已有面板最大化 / 切换能力；不要继续缩小字号或隐藏关键提交、关闭、审批操作。
4. 表单动作可以换行，字段组在自身容器内改单列。长文本换行，表格和代码只在自身区域横向滚动，不能让整个窗口横向滚动。
5. 每个独立工作区有明确的主滚动容器；仅代码、长工具输出、文件树等有实际需要时嵌套滚动。弹窗正文滚动，标题和 footer 保持可达。

密度偏好当前提供 80%–120%、每档 5%，通过 `--app-page-scale` 和 body zoom 缩放整个界面，不是只改字号。浮层容器 `#setsuna-ui-overlays` 抵消外层缩放，内容再应用密度；Feature 不重复补偿坐标。拖动边界、DOM 测量与 Electron 视口坐标按既有转换处理。

macOS 保留原生窗口按钮空间；Windows 保留标题栏控件和非最大化窗口外沿。交互元素须为 `no-drag`，拖动区不能覆盖输入、标签操作和 resize handle。仅支持这两个平台，不把窄窗口适配扩展成移动端产品。

## 5. 组件选择与交互约定

控件实现优先从 [renderer-ui](../packages/renderer-ui/src/index.ts) 复用；宿主组合组件使用 [shared/ui](desktop/renderer/shared-ui-and-styles.md)。beUI 是已有实现的设计来源，不是每次新增页面都重新引入组件库的理由。

| 需求 | 使用方式 | 必须保持的行为 |
| --- | --- | --- |
| 主要提交 | `Button variant="primary"` | 一个局部操作组只有一个主要动作；pending 防重复提交，保留按钮占位 |
| 普通操作 / 低频操作 | `secondary` / `ghost` | 工具栏默认 ghost；“更多”菜单承接低频项，不复制一排同权重按钮 |
| 破坏性动作 | `danger` 与既有确认流程 | 说明目标与后果的地方是确认内容；红色不表示所有“取消” |
| 图标动作 | `IconButton` 或宿主专用图标按钮 | 可访问名称和 tooltip 表达同一动作；有快捷键时复用 `ShortcutTooltip` |
| 文本 / 多行输入 | `TextField` / `TextArea` | 关联字段标签；placeholder 不代替标签；错误与字段关联，失败保留输入 |
| 单选 / 搜索选择 | `SelectField`、已有 ModelPicker 等 | 选择值与键盘高亮可区分；长候选可定位；复杂业务数据留在 owner |
| 开关 / 多选 | `Switch` / `Checkbox`、`CheckField` | 开关表示布尔设置，多选表示集合选择；不靠视觉动画伪装保存完成 |
| 操作菜单 | `Dropdown`、`PointMenu`、`MenuSurface` | 即开即关；支持键盘；禁用项不执行；危险项与普通项分组 |
| 小范围临时编辑 | `Popover` | 内容需要交互时使用可点击入口；必需操作不能只藏在 hover 中 |
| 短说明 / 对象预览 | `Tooltip` / 已有 hover card | 可键盘访问；tooltip 不承载必须点击才能完成任务的控件 |
| 独立表单 / 确认 | `Dialog` / `ConfirmDialog`、`useConfirm` | 共享关闭、焦点恢复和执行中状态；不另写遮罩或原生 confirm |
| 文件列表 / 数据列表 | `FileTreeSurface`、`FileTreeRow` / `Table` | 选择和数据请求归 Feature；视觉层不接管领域状态 |
| 分隔与调宽 | `ResizeHandle` | 拖动和键盘调整都可用；透明命中区、细线反馈，不套按钮背景 |
| 折叠详情 | `DetailSection` 或所属领域 disclosure | 公开展开状态；新数据不随意重置用户选择 |
| 短时操作反馈 | 既有 Toast provider | 只反馈需要告知的结果；同一结果不要同时 toast、banner、badge |

补充约束：

- `aria-current` 表示当前位置，`aria-selected` 表示集合选择，`aria-pressed` 表示切换按钮，`aria-expanded` 表示展开；不要只增加 `is-active` 样式而缺少语义。
- 设置的即时生效和表单提交不能混用：本地外观偏好可即时应用；一组有关联的服务配置沿用同一次保存。不要仅为形式统一增加保存按钮或改成逐字段自动提交。
- 共享 Dialog 的操作放在 `footer`，左右边距由 `--sd-dialog-gutter` 管理；footer 透明，不另加背景或分隔线。关闭后恢复触发位置，表单初始焦点按任务需要设置，危险确认不默认聚焦执行按钮。
- 操作确认用于既有的数据丢失、破坏或权限边界。导航、普通刷新、展开详情不增加确认。工具审批使用自己的业务流程，不能再套一层重复确认。
- 菜单的固定蓝色高亮和主界面中性选中属于两种明确场景；不要把 hover、当前位置、正在运行都画成同一种强调色。

## 6. 核心任务体验

### 6.1 对话、输入与流式结果

**阅读顺序：** 用户输入 → 本轮工作活动 / 必要审批 → 助手回复与成果。普通回复以正文为主体；长工具输出进入所属详情。工具 ID、进程 ID、内部投影编号不代替面向用户的动作名称。

Composer 的主操作沿用 [ChatComposerFooter](../apps/desktop/renderer/src/features/chat/composer/ChatComposerFooter.tsx) 的优先级：

| 条件 | 主操作 | 保留的语义 |
| --- | --- | --- |
| 队列提交就绪 | 排队 | 活动轮次中的普通提交进入队列；显式“立即发送”才走对应发送路径 |
| 存在活动轮次，未进入队列提交状态 | 停止 | 停止当前轮次，不等同于删除消息或放弃草稿 |
| 仅附件可提交 | 发送 | 附件准备期间不可提交；成功后只清理本次提交内容 |
| 其余情况 | 编辑器默认发送行为 | 遵守发送快捷键偏好和空输入规则 |

文字、结构化引用与附件按会话 / 新会话槽位独立保留；切换页面不清空草稿。发送失败保留可重试内容；迟到的上传或发送结果不能覆盖新会话。取回队列项编辑不等于删除持久化队列项。

输入法组合期间不触发发送；Shift+Enter、Enter / Cmd/Ctrl+Enter 沿用既有偏好。命令菜单先处理自己的键盘交互，不能把选择候选的 Enter 同时当作发送。模型与思考强度选择复用共享 ModelPicker；模型 ID、窗口和能力信息留在已有详情，不向 Composer 常驻追加字段。

流式增长只在用户跟随底部时跟随；用户上滚、搜索定位或拖动滚动条后保留阅读位置。加载旧历史保持锚点，回到底部才恢复跟随。普通工具 delta 不重置 disclosure；新待审批请求按既有规则显露，不把整个工作区切成阻塞层。

完整状态机与实现约束见 [Chat](desktop/renderer/chat.md)、[发送队列](designs/current/queued-turn-inputs.md)。

### 6.2 工具审批与结果

- 待审批区域展示可信代码提供的动作、目标与必要权限范围。一次允许、会话允许、持久允许、拒绝和取消轮次按实际可用决策区分，不合并成含糊的“确定”。
- 只有取得执行结果后才表达完成；点击批准、请求发出和工具执行成功是不同状态。提交失败保留当前决策上下文与重试能力。
- 审批自动审查失败、超时、拒绝沿用已有反馈；技术详情按需展开，不把整段原始 payload 放到工具栏。
- 文件变更、撤销与重新应用绑定实际操作组和持久化结果；按钮方向不能由一次本地点击永久决定。不要将工具变更撤销替换为 Git 丢弃修改。
- 外部模型、工具和插件内容按内容呈现，不能伪装成宿主授权决定或可信系统通知。

### 6.3 文件与工作区

- **收起保留会话，关闭按对象生命周期释放资源。** 底栏隐藏后恢复原标签；关闭单个终端标签按既有逻辑释放对应 session；切换会话不终止后台任务。
- 文件、审查和终端绑定项目与目录身份。不同源目录中的同名文件不能混用草稿、选中状态或异步结果。
- 文件保存失败保留草稿；保存过程中继续输入的内容仍为未保存。关闭或离开时沿用已有未保存确认，不另加常驻说明。
- Markdown 源码 / 预览切换保留编辑实例和撤销记录；带行号定位进入源码。文件定位沿用清理筛选、展开目录与滚动到目标的已有路径。
- 表格、Diff、浏览器和终端各用适合自身的阅读区域；宿主只统一面板外框与操作入口，不强迫业务内容套聊天气泡。

具体规则见 [Workspace](desktop/renderer/workspace-and-debug.md)，样式调整不得改变这些数据与资源边界。

### 6.4 设置、能力与任务管理

- Settings 以字段组为基本单位，配置表单复用 `sd-settings-form`；标题、输入、错误和提交属于同一编辑上下文。
- Plugin / Skill / MCP 目录表达实际安装、启用和来源关系；设置、权限和测试结果进入详情。敏感配置不出现在列表和 toast。
- PR 沿用列表 → 详情 → 内容标签的结构；保留筛选和列表位置，远程加载失败不冒充“无结果”。
- Automation 区分任务配置、启停和单次运行结果；编辑中的本地草稿不等同于已保存调度。复用现有时区、调度与对话语义，不另建一套运行状态。
- 可选服务未连接或加载失败只影响所属功能；不能让用户失去已有的对话和本地工作区。

## 7. 状态、反馈与文案

状态从业务数据投影，视觉不能成为第二套状态机。每个异步交互至少明确下列适用状态，但**不要求为每个状态增加常驻文字**。

| 状态 | 设计规则 |
| --- | --- |
| 首次加载 | 保留区域结构；使用已有 Skeleton / 加载入口；不要先闪现空状态，也不显示虚构进度 |
| 后台刷新 | 保留最后有效内容、选中与滚动；局部 pending，不把整个页面重置成骨架 |
| 真正为空 | 数据已成功返回后才呈现；沿用已批准的空状态和动作，组件支持 body 不代表必须补一段引导 |
| 搜索无匹配 | 保留查询与筛选，和未配置、无数据、加载失败区分 |
| 正在提交 | 禁止同一 mutation 重复触发；无关导航和输入是否可用由业务决定，不全页锁死 |
| 需要用户处理 | 审批或结构化输入在所属上下文可发现、可操作；不只使用短暂 toast |
| 成功 | 优先由结果变化表达；用户已要求的成功反馈按既定设计保留 |
| 失败 | 保留输入和最后有效数据；字段错误留在字段，局部操作错误留在局部；需要持续处理的失败不能只靠自动消失通知 |
| 取消 / 中止 | 与失败区分；明确停止的是当前操作、轮次还是会话，保留可继续的上下文 |
| 不可用 / 未连接 | 不显示为“已关闭”或“没有内容”；恢复入口沿用所属 Feature 的设计 |

现有 Toast 默认 3.5 秒、错误 5 秒，最多显示 4 条，并按内容与类型去重，见 [ToastProvider](../apps/desktop/renderer/src/app/providers/ToastProvider.tsx)。不以频繁成功通知证明后台刷新正常；Capabilities 已有的静默后台刷新失败策略继续保留。

文案规则：

- 按钮使用具体动作，名称与动作范围一致；全局术语沿用项目 i18n catalog，不在新页面混用同义词。
- 按钮旁、图标行、工具栏和详情操作区不新增“我的评分”“仅自己可见”等常驻解释。补充字段只在已要求的编辑表单或详情中表达。
- 已要求的错误与操作反馈说明实际结果及必要的下一步，不输出内部栈、token、密钥或无意义编号。技术诊断进入既有详情。
- 使用参数化 i18n，兼容中文、英文、长路径、长模型名和混合字符；不拼接句子，不用截断隐藏审批范围或破坏性后果。
- tooltip 简短并与控件语义一致；有快捷键时从统一注册表取值，macOS 与 Windows 分别显示对应组合。

## 8. 键盘、可访问性与动效

### 8.1 可访问性目标

普通正文、字段标签、菜单文字等以至少 **4.5:1** 对比度为目标；大字号文字可采用 3:1。当前 11–14px 紧凑界面不能套用大字例外。参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

承担识别功能的控件图形与必要状态标记以相邻背景至少 **3:1** 为目标；纯装饰分隔线不必全部加深。错误、选中、运行状态同时使用已有图形、形态或可访问语义，不能只换颜色。参考 [W3C 非文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。这些是设计验收目标，不是全应用合规声明。

键盘规则：

- Tab 能到达所有必要操作；按钮、链接、分隔条沿用各自的键盘焦点样式。输入框全局遵循不添加聚焦外框的约束，沿用原有字段边界、光标与选区表达输入位置。参考 [W3C 焦点可见说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)。
- 菜单内搜索与组合控件内部输入同样不添加聚焦外框，也不把外框转移到所属容器。`:focus-visible` 不能视为仅由 Tab 触发，文本输入的点击与程序聚焦也可能命中。
- hover 才出现的必要操作在 `:focus-within` / 键盘聚焦时也可访问。不能要求精确悬停才能找到关闭、更多或编辑入口。
- 菜单、选择器与 Dialog 复用 Radix 的键盘和焦点机制。Esc 先处理当前浮层，不能穿透并误触底层停止任务；非 dismissible 的执行阶段沿用业务约束。
- 输入控件有可访问名称，字段错误通过关联关系表达；图标按钮不以图形本身充当标签。
- 不给每个流式 token 使用强打断播报；错误、审批和异步结果使用已有的适当 live region。
- 拖动分隔条保留方向键调整路径。新增独立命中目标优先至少 24 × 24px；已有更紧凑嵌入控件需要同时检查间距与键盘替代，不能只检查图标尺寸。
- 80%–120% 是当前产品密度范围，不等于已覆盖全部系统放大或屏幕阅读器场景。

### 8.2 动效

动效用于解释连续关系、输入反馈和局部显隐，不延迟动作执行或承诺尚未完成的业务结果。

| 场景 | 现有基线 / 规范 |
| --- | --- |
| 按钮 hover / press | 约 150ms 颜色变化；不缩放、位移 |
| 菜单与菜单高亮 | 无展开、缩放、裁切和滑动高亮动画 |
| Tooltip / Popover | 已有 120 / 160ms 入场；不把它扩散为每个列表项的动效 |
| Dialog | 内容 180ms、上移 12px 并淡入；遮罩 160ms |
| Shell 侧栏 / 底栏 | 已有 220 / 180ms 轨道变化；拖动时关闭过渡，面板内容不重复动画 |
| 主题切换 | 既有 700ms 圆形过渡是专门场景；不作为一般动画时长 |
| 文件树、Tabs、Toast | 复用共享组件；刷新与标签重挂载不重播整区入场 |
| Reduced motion | 去掉不必要的位移、弹簧、主题揭示和光扫；滚动恢复直接定位，仍保留静态状态 |

## 9. 实现边界与性能

| 层 | 维护内容 | 边界 |
| --- | --- | --- |
| 宿主 token / preference | 主题、字体、密度、全局层级 | 不放 Feature 业务 selector |
| `packages/renderer-ui` | Button、表单、菜单、Dialog、Table 等公共实现 | 不访问 runtime，不持有项目或会话业务状态 |
| renderer shared UI | PageHeader、Panel、ShortcutTooltip、ModelPicker 等宿主组合 | 不重复实现公共控件 |
| App shell | 导航、窗口、面板轨道、overlay 组合 | 不接管 Feature 的请求与数据模型 |
| Feature renderer | 页面、业务交互、hook、局部样式与状态投影 | 复用公共能力；不以全局 CSS 改别的 Feature |
| `renderer-contracts` | 宿主插槽与注入的 UI contract | 只有真实组合需求才增加 contract |

CSS 只在所属层维护。Feature 可调布局、宽度与业务状态，不复制基础控件的颜色、禁用和焦点样式。局部例外应有明确场景和 owner；当真正跨多个 Feature 复用时再抽取，不新增万能页面组件、巨大 variant 矩阵或平行 UI 套件。

浮层沿用已有层级：Dialog 1500、图片 1700、Popover 1800、Toast 2000，由 `--app-z-*` 管理。它们是渲染层级，焦点与关闭顺序仍由组件生命周期管理；遇到遮挡先查 portal / stacking context，不盲目增加 z-index。

性能也是体验约束：

- 首屏与 runtime ready 不等待 Plugin 恢复、目录扫描、非核心数据、网络和装饰资源；UI 设计不能引入新的全局就绪门槛。
- 复杂图表、编辑器和非核心页面沿用已有按需加载路径。局部失败、慢请求只影响所属区域。
- 长对话、工具输出和大列表沿用分页、窗口化或既有增量渲染；不能为了布局便利一次加载全部历史。
- 不在每个 streaming delta 中重建昂贵观察器、菜单、编辑器或全量测量布局；尺寸测量和 pointer move 沿用已有合并路径。
- 隐藏、卸载和切换身份时按 owner 规则清理监听、动画与过期请求；不能为减少挂载成本误杀需要保留的终端或草稿。
- 新增启动步骤必须覆盖慢任务 / 失败情形并比较阶段耗时，验收以 [运行链路](architecture/runtime-flows.md) 为准。

实现细节见 [共享 UI 与样式](desktop/renderer/shared-ui-and-styles.md) 与 [Renderer](desktop/renderer/README.md)。

## 10. 设计与实现验收

按本次改动影响范围检查，不把这张表变成每次都全量运行的流程：

- [ ] 信息和操作位于正确区域；没有未经要求新增常驻说明、摘要、徽章或引导。
- [ ] 使用现有组件与 token；标题、正文、字段和元信息有明确层级，例外有真实场景。
- [ ] 涉及异步操作时，加载、空、失败、取消、重复提交和迟到响应不会破坏已有上下文。
- [ ] 涉及 Chat 时，草稿、IME、发送 / 排队 / 停止与流式阅读语义保持完整。
- [ ] 涉及文件或面板时，保存、关闭、收起、跨目录身份与后台 session 边界保持完整。
- [ ] 主题、实际色对、长内容、密度缩放与最小窗口的影响已被考虑；静态推断和实际验证明确区分。
- [ ] 相关操作有键盘路径、可见焦点和可访问名称；浮层正确返回焦点；reduced motion 有退路。
- [ ] 没有新增可避免的启动等待、全局阻塞、全量读取或持续布局测量。

涉及布局或主题时，验收场景从 macOS / Windows、880 × 640 / 1320 × 860、80% / 100% / 120%、浅色 / 深色、中文 / 英文中按影响选择交叉组合；涉及强调色时检查相关预设和状态。实际未覆盖的场景明确记录，不要求每次穷举全部组合。

文档改动检查本地链接、源码入口与 `git diff --check`。代码改动先阅读根目录 scripts，再按影响运行定向检查、typecheck 或 lint；构建仅用于确有资源、打包或构建链路影响的变更。

不新增 CSS、类名、颜色、字体、图标、布局和动画测试。仅对高收益的业务行为、数据与状态流转、实际功能交互补充测试，例如切换会话时迟到结果隔离、保存失败保留草稿、审批防重复执行。未经用户明确要求，不使用 computer-use、打开浏览器或进行样式截图验证。

设计规则变化时在本文更新取舍，组件 API 与具体状态机更新对应 owner 文档；入口只维护链接。
