# 上下文压缩执行方案

状态：三个阶段均已实施并完成真实供应商续跑评测。本文约束上下文压缩的协议、窗口状态和恢复语义；具体样本、失败和启用决策见[验收记录](../history/context-compaction-evaluation-2026-10-30.md)。

## 目标与边界

压缩后模型应继续完成同一个任务，保留有效用户约束、已验证进度、工具关联和可回查证据，并释放足够的后续执行空间。支持的 Responses 服务采用 Codex V2 同类原生压缩；其他服务使用完整输入的可移植交接。两条路径共享窗口预算、检查点安装和恢复规则。

沿用持久事件、现有 transcript、附件与工具结果存储，不创建第二套对话真源。压缩不增加启动网络请求、全库扫描或就绪等待。后台压缩通过实验性设置开关启用，原理说明放在详情弹窗中。

公开客户端协议可以对齐；原生压缩内部由供应商模型实现。文本交接的任务保持能力通过实际续跑评测验收，不能由摘要长度或接口调用成功推断。

## 数据与所有权

系统只有三种视图：

1. 持久 transcript：用户输入、模型输出、工具执行及其来源，是恢复和删除语义的真源。
2. 活跃窗口：检查点、预算内保留的原文和未压缩后缀，是下一次模型请求的历史来源。
3. 请求快照：活跃窗口加本次解析的项目/Skill/环境指令、工具定义、附件和模型参数。它是请求级临时数据，不额外持久化密钥、请求头或完整请求副本。独立端点返回的 canonical items 必须完整保留，包含的图片/文件内容同样受既有 2 MiB metadata 上限约束，超限不安装。

| Owner | 职责 |
| --- | --- |
| `packages/contracts` | 请求、压缩结果、窗口事件、回放来源与投影契约 |
| `desktop-runtime/loop/context` | 预算、保留范围、可移植交接、候选生成与生命周期 |
| `desktop-runtime/loop/core` | 同一个 sampling snapshot 的 prompt、附件、工具和配置绑定 |
| `features/model-provider/runtime` | 共用 Pi 请求转换、原生结果收集、能力判定和传输错误分类 |
| `desktop-runtime/adapters/store` | 线程写入队列内的条件安装、持久事件与恢复投影 |

检查点沿用源消息 ID，增加必要的窗口版本、覆盖边界和原生模式。窗口版本在删除、回滚、替换等改写时变化；普通追加不使捕获的稳定前缀失效。`lastSeq` 用于事件顺序，不能代替窗口版本。

## 请求与协议

普通采样和原生压缩共用模型选择、provider defaults、Pi transcript 转换、工具 ID、推理回放、附件和供应商兼容处理。压缩模式显式取消普通回答的输出格式等生成约束，不建立第二套历史序列化器。

原生模式必须区分：

- `responses-v2`：发送完整捕获窗口与实际指令、工具，末尾追加 trigger。通过 Pi 原始事件 hook 收集压缩项和 usage，等待 `response.completed`，要求唯一且可持久回放的压缩项。标准 assistant 文本为空不代表失败。
- `responses-compact`：复用相同输入转换，向独立端点发送其支持的字段，完整保存和回放返回窗口；不能再次裁剪或重复拼接已被返回窗口包含的内容。
- 可移植交接：显式摘要模型优先；否则使用当前任务模型。保留原文、摘要和实时后缀由 runtime 构建。

自定义 Responses 服务按实际能力选择协议。仅明确不支持协议/端点的响应允许降级，鉴权、限流、传输故障、残缺流和非法结果不应被当成“不支持”。能力缓存只在请求发生时建立，并绑定供应商配置身份；不增加启动探测。所有尝试共享取消与操作截止时间。

HTTP 200 后的 SSE 请求校验错误也按相同规则判断，包括被 OpenAI SDK 提前拦截、未到达原始 hook 的错误。
已经产生输出或 usage 的残缺结果不能当作能力探测失败。明确的 context overflow 返回独立状态，转入完整分批交接，不能把该模型缓存为不支持原生压缩。

## 保留策略与预算

按 token 预算保留真实用户输入和修正，利用 `promptSource`、`inputKind` 区分用户要求和 runtime 注入。调用及结果保持关联，未完成的调用组不能在边界被拆开。动态 system/developer 指令从当前配置重新构建，不把旧指令摘要提升为新政策。

可移植交接必须覆盖选定的完整源内容。分批发生在模型预算规划阶段，不能先把每条消息首尾截成固定字符数。已有摘要参与下一次交接时保持完整；摘要包含任务目标、有效约束、进度、证据、未决问题和下一步。附件保留可回放内容或可恢复引用，重要工具证据不只留下可能被回收的临时引用。

计量基于模型可见表示：文本使用 UTF-8 估算，图片及原生压缩项分别计量，传输字节上限独立处理。已观测 input usage 与匹配请求前缀形成基线；新增历史按增量计量，换模型或改写前缀后失效。基线跨 turn 持续有效，缓存 token 不重复加入上下文。

成功条件覆盖完整请求，而非仅摘要：

```text
固定指令和工具 + 压缩后历史 + 输出预留 + 续跑余量 <= 模型窗口
```

保留窗口和摘要预算都受压缩目标约束；目标必须低于触发线并留出增长余量。固定上下文本身超限、无可压缩内容、结果不达标时，保留原窗口并报告明确失败，不能无限重压缩。

## 安装、并发与恢复

```text
准备请求快照 → 规划窗口 → 生成候选 → 校验结果 → 条件提交 → 发布事件 → 继续采样
                               ↓ 失败/取消/过期
                         保留原窗口，记录实际 usage
```

安装在每线程持久写入队列内完成：重新读取当前投影，验证捕获前缀和窗口版本，只替换被覆盖部分，保留生成期间追加的完整后缀。合并后再次检查请求预算，再持久化事件与检查点，最后发布。旧的整窗口压缩事件继续兼容读取。

usage 与候选是否安装是两件事：供应商已完成但候选被丢弃时仍计入实际消耗，避免重复计费事件。取消或残缺结果不安装；失败不能把任何源消息移出活跃窗口。

切到不兼容供应商/模型时恢复源历史，再按目标窗口生成交接。删除源消息会使依赖它的原生检查点失效；回滚、fork、重启不得重新引入已删除数据。沿用现有 `nativeSourceMessageIds` 恢复机制。

## 后台压缩

后台与前台使用同一个候选生成和条件安装流程。软阈值达到时捕获稳定前缀，每线程最多一个任务；硬阈值优先接管已有候选，避免重复请求。后台结果只能在采样边界安装，不能修改正在发送的请求。

候选需校验历史、模型、endpoint 和凭据所属配置的兼容边界；追加消息允许继续，改写前缀则丢弃。失败不影响已完成回答。取消、关闭和模型变更结束相关任务；同一无进展窗口不持续重试。

轮次结束预计算与运行中预计算均已接入。用户通过“设置 → 实验性功能 → 后台上下文压缩”开关保存 `features.backgroundContextCompaction`；保存后生效，关闭时取消已有后台候选。“查看详情”弹窗分段说明触发时机、结果使用、用量与关闭行为。真实评测仍存在超时和质量波动，默认保持关闭。

## 验收

高收益自动验证覆盖以下业务不变量：

- 原生请求与普通采样的工具 ID、指令、工具定义和回放内容一致；完整流仅接受唯一压缩项，残缺/取消不会提交。
- 明确不支持时才降级；401/429/5xx、网络和非法结果不触发静默摘要，所有尝试遵守同一取消边界。
- 长消息中部证据进入摘要源；批次覆盖完整输入、跨批交接完整；摘要与保留内容共同满足目标预算。
- 生成期间追加的用户修正、工具结果保留；删除/回滚/再次压缩后旧候选不能安装；提交失败保留原窗口。
- 连续压缩、模型切换、重启恢复和源消息删除后，协议关联与模型可见窗口仍正确。
- usage 不因跨 turn 丢失，不因缓存、候选丢弃或重试重复累计。

真实供应商评测使用相同模型、历史与工具环境，对照当前行为和新实现；包含至少五次连续压缩、中文长消息中部证据、多次用户修正、图片、切换小窗口模型、取消与恢复。记录任务完成、关键约束保持、证据复用、重复工具动作、再次压缩间隔、前台阻塞 p50/p95 和 token 成本。

检查顺序为定向 unit/integration、`pnpm typecheck`、相关 lint 与 `git diff --check`。涉及恢复与公共投影后扩大到完整测试；不因文档或纯逻辑改动反复 build。
