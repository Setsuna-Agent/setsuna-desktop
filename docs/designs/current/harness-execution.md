# Harness 执行与验收

状态：已接入 runtime。本轮实现包括程序化工具调用、可回读工具工作集和 Goal 独立完成验收。目标是提高长任务的完成可靠性，并减少工具密集任务的上下文成本；产品收益仍需要同模型、同预算的真实任务对照，不能用单测通过率替代。

## 实施范围与顺序

1. 工具执行基础：统一最终参数的审批检查、有界并发和取消收口。PTC 的嵌套调用复用同一条执行链，不能建立第二套权限系统。
2. 工具结果工作集：在已有 ToolResultStore 中保留有价值的工具原文；在上下文压力下将较早结果替换为可回读引用。保留最近结果、失败、附件、用户要求和 assistant 原生推理；摘要仍作为后续兜底。
3. 程序化工具调用：提供 `run_code`，在按需加载的隔离 JavaScript 环境中组合已授权工具，只把显式输出送回模型。限制时间、内存、调用数、并发及输出，不向程序暴露 Node、文件系统、网络或宿主对象。嵌套执行仍持久化审计记录。
4. Goal 完成验收：完成请求触发独立、无工具的证据审查，检查原始目标、执行结果与交付物，而不是只接受模型的完成声明。审查记录由 Goal Feature 持久化；失败反馈进入修复循环，后续工作使旧审查失效。验收失败与预算必须有界，取消和恢复不能误标完成。

## 所有权与约束

- Goal 私有验收状态与 codec 属于 `packages/features/goal`；Core 提供模型采样和事件适配。
- PTC 协调属于 runtime tools；隔离引擎属于 adapter。按需创建执行环境，不增加 runtime ready 或 renderer 首屏的等待。
- 上下文投影保留事件真源，不覆盖原始消息。引用按线程授权；存储失败或结果已淘汰时保留可用内容，不能静默丢弃。
- 不新增 UI 文案。验收服从用户和仓库规则，不能强制全量构建、浏览器验证或无价值测试。
- 保留普通工具调用，PTC 适用于条件查询、批量读取和结果筛选；禁止递归调用 PTC 或绕开权限过滤。
- macOS / Windows 共用实现；隔离运行时不依赖本机编译工具或新增平台服务。

## 程序执行协议

设计参考 [Codex Code Mode 的工具协议（固定修订）](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/code-mode-protocol/src/description.rs)。本轮吸收工具代理、显式输出和显式数据保留；不把所有细节一次移植。

```text
run_code({ code }) → disposable Worker / QuickJS WASM
                   → tools.NAME(args)
                   → 有界调度 → 现有 ToolHost / hooks / approval
                   ← { content, tool_call_id, result_id? }
                   → text / print → 父工具结果 → 下一次模型采样
```

- 当前各供应商共用 JSON tool schema，入口为 `run_code({ code })`。支持 JavaScript、顶层 `await`、`Promise.all` 和条件/循环；直接接收原始源码的 freeform tool 协议需要模型供应商层另行支持。
- 每次执行创建新的 QuickJS context；普通变量消失。`text`、`print`、`console.log` 输出文本，根表达式返回值和中间工具结果不自动进入模型上下文。工具返回失败会拒绝 Promise，可在脚本中捕获。
- `tools` 只包含当前请求经过权限过滤的 host 工具及 runtime 的 `search_tools` / `read_tool_result`。`ALL_TOOLS` 提供名称与描述，未知 schema 用 `search_tools` 查询。Goal、协作、AppServer 动态工具与递归 `run_code` 不进入程序目录。
- 程序没有 Node、宿主文件系统、网络、包导入能力；真实外部操作必须走工具代理。引擎及内嵌 WASM 仅在首次执行时由 Worker 加载，runtime ready 不等待它。
- 嵌套工具继续发布开始/结束事件和 transcript-only 结果，返回程序的是 hooks/extensions 处理后的文本；图片等附件复用既有资产链路附加到父结果。工具批次另行返回记忆保存状态：成功的 `remember_memory` 即使后续脚本失败也抑制轮次结束时的重复自动保存；保存失败则保留既有兜底逻辑。
- `store(key, value)` 保存 JSON，`load(key)` 返回反序列化副本，状态仅在线程内共享。最多 128 键、单值 2 MiB、线程总计 4 MiB；最多保留八个线程的状态，达到上限淘汰最久未使用且无运行程序的线程。执行退出时回传一次有界快照，避免连续 store 淹没宿主 IPC；强制终止可能丢失本次尚未同步的写入。删除线程或关闭 runtime 清理状态，不跨重启恢复。
- 每个线程同时最多一个程序，runtime 最多四个；每个程序最多 64 次工具调用、六个可并行操作、64 MiB QuickJS heap、64 KiB 文本输出。源码 32 KiB、单次工具参数 256 KiB、桥接值 2 MiB。大文本可通过 `result_id` 分页读取。
- 120 秒是执行截止时间，包含工具等待；取消/到期/失败终止 Worker、取消排队和在途工具并等待收口。已经产生的工具副作用不回滚，重试前必须检查。写操作依赖原有事务与权限机制。

示例：

```javascript
const pages = await Promise.all([
  tools.read_file({ file_path: 'README.md' }),
  tools.read_file({ file_path: 'package.json' })
]);
store('inspection', pages);
text(pages.map(page => ({ call: page.tool_call_id, excerpt: page.content.slice(0, 500) })));
```

后续若真实任务表明程序经常超过截止时间，再加入 `exec/wait`、增量输出与显式 cell 生命周期；`yield_time_ms` 必须与执行超时独立。`image`、`notify` 和 freeform 源码也属于后续协议扩展，当前未实现。

## 工具观察工作集

统一输出边界保存至少约 1024 token 的中型结果和超限结果。模型窗口超过 40K token 或可用对话窗口的 70% 时，从旧到新把可读取的成功结果投影为 `result_id` 信封；最近六个结果、错误、附件、本地存储已截断的结果、用户消息、assistant 内容和原生推理不动。本地截断只保存前缀，保留原消息才能保住无法回读的可见尾部。缺失/淘汰/读取失败的引用不能取代已有正文。

每次采样将原始对话来源与模型投影分开；下一轮保留正文，必要时再用持久 transcript 快照恢复已有引用，然后检查存储可用性和投影预算。后续输出触发配额淘汰或临时采样快照读取失败时，仍保留原始可见内容。保留 tool call ID 和消息顺序，重新校准投影后的预算，再进入既有摘要/原生压缩流程。压缩事件落盘前恢复所有工具引用的正文，包括归档为 transcript 的消息；投影只用于模型窗口，不覆盖持久历史。引用内容是历史观察，不能替代当前工作区检查。

## Goal 验收与修复状态机

`update_goal({ status: 'complete' })` 不直接提交完成：

1. 读取原始 objective、当前模型配置、作用域指令及历史证据。证据最多 60 条/64 KiB，记录工具参数、消息 ID、成功/错误和截断标记；按事件序号把工具执行与结果消息配对，优先使用完成事件中的最终参数，再以稳定消息 ID 索引，避免同轮/跨轮复用 tool call ID 或模型协议改写造成串联。项目指令保留 role/source/trust 信息。
2. 使用当前任务模型独立采样，禁止工具调用，90 秒截止，要求逐项 JSON 结论。模型请求在 Goal 修改队列之外执行，取消、暂停和清除不等待验收响应。验收 token 进入现有用量链路及 Goal 累计计量；普通非 Goal 回答不增加验收采样。
3. 写回时重新进入修改队列，以读取时的事件序号检查 Goal 修订，并再次校验取消与当前状态；编辑后改回原目标也会使在途验收失效。仅当前修订的结论可写入 `goal.verification-recorded@1`。检查项、证据 ID 或通过条件无效、非正常结束或无法验证都返回缺口，不默认成功。
4. 失败返回执行模型继续修复；同一 turn 三次失败把 Goal 置为 blocked，并登记待结算的退出消息。最终轮次用量结算后，仅发布一次带具体缺口和最终用量的退出总结；清除、替换或恢复 Goal 不沿用旧退出标记。用户继续后仍走现有调度规则。
5. 通过只建立本 turn 的待完成标记。后续非 Goal 工具操作或用户消息使它失效，终止前提示重新验收；最终结算再检查一次。只有最终回答正常结束才提交 complete，截断、取消、异常或重启均不能误完成。

该机制是独立证据审查，不是形式化证明：同一模型仍可能判断错误；未经过 runtime 事件的外部文件变更不自动失效，纯图片/二进制交付物也未做独立内容验收。不得宣称它能替代实际行为测试，或把执行模型的成功声明当作外部工作证据。

## 验证

- 定向行为测试覆盖：缺失/伪造证据、事务内及跨事务工具 ID 复用、修复后通过、证据失效、失败次数、最终截断及阻塞退出的完整计量；验收挂起期间的取消/暂停/清除、改走再改回目标时拒绝旧结论；线程状态隔离、实际 Worker 取消、并发上限、排队取消、改写后的审批和真实文件覆盖保护；嵌套记忆保存成功/失败及保存后脚本失败；连续采样间的真实配额淘汰、自动压缩后重新加载原文、快照读取失败、错误/附件及近期结果保留。现有 Goal 取消/恢复、输出存储和协议测试继续验证原链路。
- `scripts/test/tool-program-bundle.test.ts` 使用生产 esbuild 配置生成独立 CJS Worker，实际运行其内嵌 WASM；release 测试加入程序 adapter 用例供 macOS/Windows 执行。本地 macOS 通过不等于已完成 Windows 实机验收。
- 产品收益另用真实任务对照：固定模型、预算、权限、环境；记录完成率、用户补充提醒、工具/模型调用数、缓存 token、实际费用与耗时。先用代表性任务筛选，再用留出任务复验。
- 可将完成率增加约 10 个百分点，或完成率保持且费用/耗时降低约 25%，作为验收目标；当前没有宣称已达到这些目标。
